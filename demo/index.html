AI OS Framework Demo

Build a control plane, not just another pile of agent scripts.

This demo shows the smallest useful version of the framework: thin subsystem contracts, a shared War Room snapshot, and an operator-facing surface that turns scattered signals into priorities, risks, and next actions.

Open War Room Demo View Architecture Diagram

What this demo proves

You can keep subsystem internals separate, publish explicit contracts, and still give operators one clear place to understand what matters now.

One control plane Runtime aggregation lives in one place instead of being buried inside each subsystem.
Contract-first integration Trading, knowledge, and email each publish a thin daily_summary.json.
War Room as the operator surface The control plane turns subsystem outputs into executive priorities, risks, and actions.

Quick start

1. Bootstrap the demo Run bash scripts/bootstrap.sh or make bootstrap.
2. Generate sample output The demo writes output/war_room_snapshot.json.
3. Open the operator view Launch demo/war_room/index.html in your browser.
This is intentionally small. The goal is to show the operating model clearly before you add real runtimes, schedulers, or host-specific adapters.
